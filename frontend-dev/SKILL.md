# Frontend Dev

根据原型截图自动生成前端页面代码的完整工作流程。

## ⚠️ 重要说明

**使用本 SKILL 时，必须严格按照以下工作流程逐步执行。**

## 🛑 人工确认点总览

本技能在以下关键节点需要人工确认：

| 确认点 | 位置 | 确认内容 |
|--------|------|----------|
| **确认点 1** | 步骤2 → 步骤3 | 前端框架、组件库、项目结构 |
| **确认点 2** | 步骤4 代码审查后 | 审查结果、样式问题、优化建议、是否调整代码 |
| **确认点 3** | 步骤5 → 步骤6 | 是否确认执行 Git 提交流程 |

## 🎯 特殊指令处理

当用户指令为**"审查前端页面代码"**时，自动执行以下步骤：
- **步骤1**: 解析原型截图
- **步骤4**: 代码审查与自动调整 ⚠️ **需要人工确认**
- **步骤5**: NPM 启动与自动修复
- **步骤5 → 步骤6**: Git 提交流程确认 ⚠️ **需要人工确认**
- **步骤6**: 自动 Git 提交

**注意：** 此场景下跳过步骤2（确定前端框架和组件库）和步骤3（生成前端代码），直接对现有代码进行审查和优化。在步骤4和步骤5→步骤6执行前，必须等待用户确认。

## 工作流程

### 1. 解析原型截图

使用 MCP `image_parse` 和 `image_to_dsl` 工具解析截图。

**注意：** 解析时需要尽可能精确地提取所有视觉信息、文案信息，包括像素级的细节、组件尺寸、间距等，以确保生成的页面与原型高度一致。

### 2. 确定前端框架和组件库

按以下优先级确定前端框架：

1. **用户明确指定** - 如果用户在描述中明确提到使用某个框架（如"用 React"、"使用 Vue3"），则使用该框架
2. **检测现有工程** - 如果用户在现有项目中工作，检测项目配置文件：
   - Vue3: `package.json` 中包含 `vue` 且版本 >= 3.0，或存在 `vite.config.js`/`vue.config.js`
   - React: `package.json` 中包含 `react`，或存在 `webpack.config.js` 且包含 React 相关配置
   - Angular: `package.json` 中包含 `@angular/core`
3. **默认选择** - 如果以上都不满足，默认使用 **Vue3** 框架

根据确定的前端框架选择对应的组件库：

- **Vue3**: 使用 **Element Plus** 组件库
- **React**: 使用 **Ant Design** 组件库
- **Vue2**: 使用 **Element UI** 组件库
- **Angular**: 使用 **NG-ZORRO** 组件库

**组件库选择优先级：**

1. **用户明确指定** - 如果用户明确指定了组件库（如"使用 Vant"、"使用 Naive UI"等），则优先使用用户指定的组件库
2. **检测现有工程** - 如果用户在现有项目中工作，检测 `package.json` 中已安装的组件库，优先使用项目已有的组件库
3. **默认选择** - 如果以上都不满足，使用框架对应的默认组件库

**注意：** 如果用户指明了组件库但 `package.json` 中没有相关引用，则使用用户选择的组件库，并在生成的代码中添加相应的依赖安装说明。

#### ⚠️ 人工确认点

**在进入步骤3之前，必须等待用户确认以下内容：**

- ✅ 前端框架选择（Vue3/React/Angular/Vue2）
- ✅ 组件库选择（Element Plus/Ant Design/Element UI/NG-ZORRO 或用户指定的其他库）
- ✅ 项目结构规划

**确认方式：** 向用户展示确定的技术栈和项目结构，使用以下格式：

```
请确认以下技术栈和项目结构：

【前端框架】XXX
【组件库】XXX
【项目结构】XXX

是否确认继续生成代码？可回复"确认"、"同意"或提出修改意见以进入下一步
```

### 3. 生成前端代码

根据解析结果和确定的框架生成代码：

#### 代码生成原则

- **保持设计还原度**：严格按照解析结果中的样式信息（颜色、字体、间距等）
- **组件化设计**：将页面拆分为可复用的组件
- **代码规范**：Vue 文件内容必须按照 `template`、`script`、`style` 的顺序编写

#### 代码结构

```
src/
├── components/          # 可复用组件
├── views/              # 页面组件
├── assets/             # 静态资源
├── styles/             # 样式文件
└── utils/              # 工具函数
```

#### 样式处理

- 使用 CSS 变量存储设计系统中的颜色和字体
- 保持与原型一致的间距和布局
- 使用 Flexbox 或 Grid 实现布局

### 4. 代码审查与自动调整

**必须**进行还原度、样式细节、组件选择、代码优化建议等审查，并根据审查结果自动调整前端代码

#### 审查内容

1. **还原度审查**：对比生成的页面与原型截图，检查布局、组件、文案是否一致
2. **样式细节审查**：检查颜色、字体、间距、边框等样式细节是否准确
3. **组件选择审查**：评估使用的组件是否合适，是否有更优的组件选择
4. **代码优化建议**：分析代码质量，提供优化建议

#### ⚠️ 人工确认点

**在调整代码之前，必须等待用户确认以下内容：**

- ✅ 还原度审查结果（列出发现的问题）
- ✅ 样式细节问题（列出需要调整的样式）
- ✅ 组件选择是否合适（如有更优选择需说明）
- ✅ 代码优化建议（列出具体的优化点）
- ✅ 是否同意进行代码调整

**确认方式：** 向用户展示完整的审查报告，使用以下格式：

```
是否确认按上述建议调整代码？可回复"确认"、"同意"或提出修改意见以进行代码调整
```

等待用户回复"确认"、"同意"或提出修改意见后方可执行代码调整。

### 5. NPM 启动与自动修复

代码生成后，执行以下操作：

#### 启动开发服务器

1. **检查项目配置**：查看 `package.json` 中的启动脚本
2. **启动开发服务器**：使用 `npm run dev` 或 `npm start` 启动项目
3. **等待服务启动**：确保开发服务器成功启动并监听端口

#### 自动修复问题

启动过程中或启动后，自动检测并修复问题

**自动修复流程：**

1. 监控启动日志，识别错误信息
2. 根据错误类型自动选择修复方案
3. 执行修复操作
4. 重新启动服务验证修复结果
5. 如仍有问题，重复上述步骤

#### ⚠️ 人工确认点

**在进入步骤6之前，必须先询问用户是否确认进行 Git 提交。**

**确认方式：** 使用以下格式询问用户：

```
请确认是否执行 Git 提交流程？

即将执行以下操作：
1. 检查 Git 状态（git status）
2. 查看修改内容（git diff）
3. 生成提交信息
4. 执行 Git 提交

是否确认执行？可回复"确认"、"同意"或"跳过"
```

等待用户回复后，按以下方式处理：
- **"确认"、"同意"**：执行步骤6的 Git 提交流程
- **"跳过"**：跳过步骤6，结束整个工作流程
- **其他内容**：视为修改意见，根据用户意见调整后再次询问

### 6. 自动 Git 提交

执行 Git 提交操作：

#### 提交流程

1. **检查 Git 状态**：使用 `git status` 查看当前修改的文件
2. **查看修改内容**：使用 `git diff` 查看具体修改内容
3. **添加修改文件**：使用 `git add` 添加所有修改的文件
4. **生成提交信息**：根据修改内容自动生成清晰的提交信息
5. **执行提交**：使用 `git commit` 提交代码

#### 提交信息规范

提交信息应遵循以下格式：

```
feat: 根据原型生成前端页面

- 生成 [页面名称] 页面组件
- 使用 [组件库名称] 组件库
- 实现页面布局和样式
- 添加交互功能
```

或

```
fix: 优化页面样式和交互

- 调整 [具体样式] 以匹配原型
- 优化 [具体功能] 的交互体验
- 修复 [具体问题]
```

#### 注意事项

- **提交前确认**：确保所有修改都已通过审查和优化
- **提交信息清晰**：提交信息应准确描述本次修改的内容和目的
- **避免提交无关文件**：只提交与本次任务相关的文件
- **分支管理**：如果项目使用分支管理，确保在正确的分支上提交

#### 执行命令示例

```bash
# 查看当前状态
git status

# 查看修改内容
git diff

# 添加所有修改的文件
git add .

# 提交代码
git commit -m "feat: 根据原型生成前端页面"
```
