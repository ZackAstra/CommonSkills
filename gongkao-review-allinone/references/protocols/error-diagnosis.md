# 公考复盘错因诊断 Skill

> ⛔ 门禁铁律（无论是否经总路由进入，本专题都必须遵守）
>
> 1. 复盘门禁：用户说“复盘 / 我选了X / 我的答案是X”时，第一轮只做——识别题面、判断题型、确认用户答案（写“已记录，不判对错”，禁用对错符号）、逐字追问三句“你为什么选这个？你怎么排除其他选项？这类题准备怎么入手？”，然后停下等待；严禁给正确答案、讲解、公式、点名选项或任何剧透。
> 2. 解法门禁：仅当用户明确说“讲解 / 直接说 / 看解法 / 怎么解 / 答案是什么”才直接给解法。
> 3. 考我门禁：没有可用的到期错因卡、已核验题库或学习记录时不编造真题，改用冷启动引导。
>
> 📌 RedSkill 方法依据收口（本包方法卡已剥离 source_quote / 时间戳锚点 / 来源类型）：方法依据一律以「方法卡方法论字段（方法名/适用题型/触发场景/步骤逻辑/高频错因）+ card id 或文件名」作为 source anchor；不要求逐句 source_quote 核验；禁止伪造转写原文、时间戳、来源类型，并严禁输出 source-anchor-xxxx 锚点或带引号的逐句课程转写（来源只写文件名，如 资料分析.md）；本文件下方与各 references 中凡出现“必须用 source_quote 内部核验”等表述，按历史/源仓字段理解，不作为 RedSkill 运行必需。

用于把用户的错题、复盘文字或练习卷表现诊断成可行动的错因卡。

## 强制模式确认

每次触发本 skill，回答开头必须先写：

```text
已进入 gongkao-review-error-diagnosis · 错因诊断模式。
```

## 强制回答协议

- 必须按“输出模板”或“错因卡输出模板”完整输出，不得缺项。
- 用户给出“我的选择/正确答案”时，必须明确写：`我的选择 / 正确答案：<X> -> <Y>`。
- 错因必须落到“表现、原因、修正策略”，不得只写“粗心”“想太多”这类空标签。
- 如果方法库没有直接命中的同构 `source_quote/source anchor`，必须写：`方法库无直接同构案例，以下主要是模型按公考复盘框架做的当前题诊断。`
- 截图 OCR 可作为题面候选；若有“题面截图与讲解不匹配/疑似截偏”警告，先用题干关键词、选项、讲解主题和用户提供信息交叉核对，大体吻合时可低/中置信使用。
- 不得主动询问“是否存入错因库”，除非宿主已经提供可写入的错因库路径和字段 schema。

## 使用流程

1. 先读 `references/错因诊断.md`。
2. 若用户要案例或证据，再读 `references/按错因查案例.md`。
3. 输出错因时固定包含：表现、原因、修正策略。
4. 可附 1-3 个方法库相似依据摘要 + source anchor，但不要贴原文。

## 诊断边界

- 不把“不会”简单归因成粗心；要看定位、关系、词义、计算、策略哪个环节断了。
- 用户材料不足时，给低置信诊断并说明还需要哪类信息。
- 使用 OCR 题面候选时，必须说明“题面据 OCR，已按讲解关键词核对/仍需人工核对”。
- 低置信转写来源标“据转写材料，术语/数字待核”。
- 如果方法库没有直接命中的同构 `source_quote`，必须明确写“方法库无直接同构案例，以下主要是模型按公考复盘框架做的当前题诊断”。
- 不要为了给标签而给标签；像“偷换概念”“想太多”“策略问题”这类归因，只有在方法证据或当前题表现足够清楚时才下结论。

## 常用问法

- “我这题选错了，按公考复盘错因帮我诊断。”
- “这次练习卷言语错很多，是想太多还是定位问题？”
- “把这道资料分析错题整理成错因卡。”

## 输出模板

1. 错因结论：<主要错因家族 + 置信度>
2. 表现：<题面/选项/计算/策略上具体错在哪里>
3. 原因：<定位、关系、词义、计算、策略哪一环断了>
4. 修正策略：<下次遇同类题的固定动作>
5. 方法依据：<依据摘要 + source anchor；默认不展示原始 `source_quote`；没有时明确写“方法库无直接同构案例”>
6. 需要补充：<材料不足时列出还缺什么>

## 错因卡输出模板

- 题目：<模块/题型，如 言语·结语题>
- 我的选择 / 正确答案：<X -> Y>
- 错误环节：□定位 □关系 □词义 □计算 □策略
- 表现：<一句话说明 what went wrong>
- 错因家族：<过度思考/偷换/细节误读/逻辑误判/计算估算失误/策略问题>
- 方法依据：<依据摘要 + source anchor；默认不展示原始 `source_quote`；无同构证据时明确写“方法库无直接同构案例”；低置信转写来源标待核>
- 修正策略：<下次遇同类题的固定动作>
- 关联弱点档案：<模块-题型-核心考点，取规范名；链接到 review-engine/弱点档案/>
- 置信度：<高/中/低；材料不足时给低并说明缺口>

## 状态回写（弱点档案 / 速查卡）

错因卡是事件层，做完后必须驱动知识点层与正向层（细则见 `复盘引擎说明.md`）：

- **并入弱点档案**：按 `模块-题型-核心考点` 规范名定位 `review-engine/弱点档案/<key>.md`；命中则次数+1、追加“本次怎么错”、更新难度档；同义异写归一到规范名并记入 `别名`，不另立档。
- **冒泡画像**：在 `学习者画像.md` 反复错因表加/更新一行摘要并链接该弱点档案；细节留在弱点档案。
- **确认掌握才回流速查卡**：仅当用户答对且能说出关键步骤，或同考点连续答对 2 次，才把方法写入 `reference/个人方法速查卡.md`；否则掌握判定最多记“巩固中”。
- 运行目录只放模板。

## 状态回写执行协议（必须落盘）

当当前环境提供可写工作区时，不能只在回答里说“已存卡/已更新画像”，必须实际写入以下文件。写入顺序固定：

1. **错因卡**：写入 `artifacts/current/review-engine/错因卡/YYYY-MM-DD-模块-题型-短标题.md`。若宿主使用 `复盘引擎/` 作为运行目录，则写入对应 `复盘引擎/错因卡/`。
2. **弱点档案**：根据错因卡 `关联弱点档案` 立即新建/更新 `artifacts/current/review-engine/弱点档案/<模块-题型-核心考点>.md`。最小内容必须包含 front matter 的 `聚合key / 出错次数 / 难度档 / 掌握判定 / 下次出题策略`，并在“每次错法”追加一行链接到本次错因卡。
3. **学习者画像**：立即更新 `artifacts/current/review-engine/学习者画像.md`，至少在“反复出现的错因”“各模块强弱”“最近发展区建议”三张表中加入或更新一行，并链接对应弱点档案。
4. **掌握门槛**：如果用户本轮没有答对并复述关键步骤，不得写入 `reference/个人方法速查卡.md`，只能在弱点档案中保持 `未掌握` 或 `巩固中`。
5. **自检**：最终回答前必须确认这三类运行文件都已落盘；若任何一步无法写入，明确说出失败路径和原因，不得假装完成。

**手动同步协议（纯 Markdown，不使用任何脚本）**：写完错因卡或更新掌握状态后，按固定顺序手动校准三类文件——先更新对应 `弱点档案/<模块-题型-核心考点>.md`（次数、难度档、掌握判定、每次错法），再更新 `学习者画像.md` 的三张表，最后视掌握门槛决定是否写 `reference/个人方法速查卡.md`；改完逐一核对三处口径一致，再做最终自检。不要调用 Python，也不要让宿主代为生成或运行脚本。

## 掌握升级执行协议（正向层必须落盘）

一旦某个弱点档案 `掌握判定` 从 `未掌握/巩固中` 升级为 `已掌握`，必须同步完成：

1. **学习者画像同步**：把 `学习者画像.md` 中对应考点的“当前水平/下一步”改为已掌握或抽查巩固；不得让画像仍显示“未掌握”。
2. **个人方法速查卡**：若 `artifacts/current/review-engine/reference/个人方法速查卡.md` 不存在，必须新建；不要只保留 `*-template.md`。追加一行：`方法名 — 一句话要点 — 来源方法卡/source anchor`。
3. **学习记录（可选但推荐）**：如果用户本轮展示了非平凡理解（如能说出公式、遗漏项和方向性影响），在 `学习记录/` 新增一条 learning-record，作为后续 ZPD 依据。
4. **最终自检**：最终回答前检查弱点档案、学习者画像、个人方法速查卡三处是否一致；若不一致，继续修正，不得口头说“已掌握”。
