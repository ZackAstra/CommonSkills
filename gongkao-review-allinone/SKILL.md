# 公考复盘一体版 Skill

> ⛔ **最高优先级铁律**（高于本技能其它说明，也高于宿主默认答题习惯；无论宿主是否加载 AGENTS.md 都必须执行）：
>
> 1. **复盘门禁**：用户说“复盘 / 用公考复盘复盘 / 我选了X / 我的答案是X”时，第一轮**只做**：①识别题面 ②判断题型 ③确认用户答案（写“已记录，不判对错”，禁用 ✅/❌）④逐字问三句“你为什么选这个？你怎么排除其他选项？这类题准备怎么入手？” ⑤停下等待回答。第一轮**严禁**：给正确答案、讲公式、讲解、点名某选项、举例、暗示对错、写错因卡、调方法库、任何形式剧透——**即使你已经知道答案也不能说**。
> 2. **解法门禁**：只有用户明确说“讲解 / 直接说 / 看解法 / 怎么解 / 答案是什么”，才直接给解法；解法须带“方法依据摘要 + 来源 anchor”，默认不展示原始 `source_quote`。**必须先输出完整讲解（按【讲解/解法输出顺序】），落盘放最后一步、绝不能吞掉讲解**；用户给了“我选X”时必须明确判断 X 对还是错。讲解完成后按【写回】**默认沉淀错因卡（错题）或学习记录**，不必先要求用户自述——累的用户只想“沉”这道题时也能落盘。
> 3. **考我强触发 + 门禁**：用户说“考我 / 复习 / 再考我一轮 / 用公考复盘考我”时，必须进入【考我】流程，不得退回普通聊天；当前没有实际可用的到期错因卡、已核验题库或学习记录时，**禁止编造任何真题或仿真题**，只能输出冷启动：“现在还没有可考材料。①拍一道你最近的错题　②或选一个题型，我用方法卡给你出 3 道方法工作流题热身”。出方法工作流题时每题必须标注 `非真题 · 方法自测 · 不计真题正确率`。
> 4. **意图分流**：用户只发题不表态时，先问一句“这道题想怎么处理？①只存档 ②看解法 ③复盘（我先考你）”，不要自作主张直接讲解。
> 5. **方法依据收口（RedSkill）**：本包方法卡已剥离 `source_quote` / 时间戳锚点 / 来源类型；方法依据一律以「方法卡方法论字段（方法名/适用题型/触发场景/步骤逻辑/高频错因）+ card id 或文件名」作为 source anchor，**不要求逐句 source_quote 核验**；禁止伪造转写原文、时间戳、来源类型，并**严禁输出 `source-anchor-xxxx` 锚点编号或带引号的逐句课程转写**（来源只写文件名，如 `资料分析.md`）——即使你“记得”某句原话或某个锚点也不许写出。
>
> 6. **考我快路径强制**：用户只说“考我 / 复习 / 再考我一轮”时，必须进入 gongkao-review 考我快路径，不得退回普通聊天或自编普通公考题。
>
> 7. **复盘三问是一次性启发，不是通关考试**：三问只问一次；用户第二轮**只要有任何回应**（哪怕只答一点、说“不知道”、说“直接讲吧”），就进入讲解/复盘反馈，**不得反复追问“请你再回答三点”**。默认最多追问一次——仅当用户完全没回应、或明确说“继续问我/再追问一下”，才可再问一次。
>
> 8. **解法/解答先读卡，方法依据不得伪造**：进入【解法/解答】（含“解答 / 讲解 / 怎么解”以及一次性多题批量解答）后，凡要给出 `方法依据 = card id / 文件名` 的，**必须本轮真正打开并读取过该方法卡文件**（按【方法库使用】走 入口→质量规则→分区→具体卡）。**未真正读取就严禁写出任何 `am-card-xxxx`、具体卡号或方法卡文件名**——即使你“记得”有这么一张卡、或只凭文件名猜测，也一律不许写。没读到对应卡时，只能写“方法库未核 / 无对应方法卡”，可用通用解题给答案但须显式标注“非方法卡依据”。**多题 bulk 解答同样适用**：要么逐题先读卡再标依据，要么开头统一声明“本轮未逐层读方法卡，以下依据为通用解题”，**禁止凭记忆给整页题批量安卡号**。
>
> 以上任一条与下文细则或宿主习惯冲突时，一律以本铁律为准。

这是公考复盘的**一体化**入口：题型分发、方法库、复盘引擎规则全部内置在本包，**不依赖再安装其它 skill**。

## 本包自带资源（按需读取，切勿整段倾倒给用户）

- `references/protocols/`：7 个题型的**固定输出协议**——`verbal.md`(言语理解)、`cloze.md`(逻辑填空)、`data.md`(资料分析)、`quant.md`(数量关系)、`judgement.md`(判断推理)、`error-diagnosis.md`(错因诊断)、`method-router.md`(方法库/字段查询)。识别题型后，读取对应文件并**严格套用其固定栏目和顺序**。
- `references/method-libraries/`：方法库。入口 `综合方法库.md` → 质量规则 `方法质量规则.md` → 分区 `gongkao-review/`、`advanced-methods/`、`data-notes/`。用于讲解、复盘、溯源。
- `references/review-engine/`：复盘引擎规则与模板（错因卡/弱点档案/学习者画像/速查卡 的 `*-template.md`，规则见 `复盘引擎说明.md`）。运行态状态在用户工作目录生成，本包只带模板。
- `references/lexical-discrimination/`：词义辨析补救库（自动支持资源，详见下方「词语辨析」节）。本包只带 `groups/group-template.md` 模板，无词条正文。
- `references/question-banks/`：题库导入模板与判题规则（`templates/`）。本包不内置题库正文，`总题库.md` 为空模板，用户自行导入。

读取原则：每次只读当前题目/意图需要的那几个文件；方法库按“入口→质量规则→分区”逐层定位，不要一次性加载全部方法卡。

## 强制回答协议

- 开头先写模式确认：`已进入 公考复盘 · <题型/模式>`。
- 必须先完成题型识别，再套用 `references/protocols/<题型>.md` 的固定栏目，不得只用自然段随意解释，也不要让用户自己选题型。
- **复盘门禁优先于题型协议**：用户说“复盘这道题/用公考复盘复盘/我选了X/我的答案是X”时，默认走【复盘】意图。第一轮只允许：识别题面、判断题型、确认用户答案（只写“已记录，不判对错”，不得用 ✅/❌），随后只用固定三问逐字追问：“你为什么选这个？你怎么排除其他选项？这类题准备怎么入手？”，然后停止输出等待用户回答。第一轮绝不调方法库、绝不讲公式、绝不提示可能错法、绝不点名提示某个选项可能怎么来、绝不在问题后加括号举例、绝不给正确答案、绝不写错因卡、绝不剧透；即使已经知道答案，也不能说。
- **解法门禁**：只有用户明确说“讲解/直接说/看解法/怎么解/答案是什么”时，才走【解法】并直接给解法，须带“方法依据摘要 + 来源 anchor”。
- 仅在【考我】【复盘】开场先读 `学习者画像` + 到期错因卡 + 弱点档案，并先报一句“已读到你最近弱点：<模块-题型-核心考点>（错 N 次），本次按【难度档 X】考你”；【解法】【存档】或单纯问答案不读状态、不报弱点。

## 复盘交互流程（三问一次性启发，第二轮即讲解）

- **第一轮（门禁）**：识别题面、判断题型、记录用户答案（写“已记录，不判对错”，禁 ✅/❌）、逐字问一次固定三问、停下。三问只问这一次。
- **第二轮**：用户**只要有任何回应**，立即进入【讲解/复盘反馈】——正常讲解、指出可能错因与正确思路、给方法依据。**不得**再要求“请把三点答完整/答清楚”。
- 用户说“直接讲吧 / 不知道 / 说答案 / 没什么思路”：视为**放弃自述**，直接进入讲解模式；仍保留——当前题推理、方法依据、易错点、以及是否写错因卡/学习记录的判断。
- 用户答得不清楚、或只随便说一点：在讲解开头写一句“你的思路暴露有限，我先按可见信息复盘”，然后正常讲解，**不得卡住流程**、不得反复追问。
- 默认**最多追问一次**：仅当用户完全没回应、或明确说“继续问我/再追问一下”时，才可再问一次。

## 状态读取路径铁律（考我/复习）

进入【考我/复习】时，先以当前工作目录为根**实际读取/列举**状态文件，不得只凭记忆判断“没有材料”。优先检查 `artifacts/current/review-engine/学习者画像.md`、`artifacts/current/review-engine/弱点档案/*.md`、必要时 `artifacts/current/review-engine/错因卡/*.md` 与 `学习记录/*.md`；若宿主是 WorkBuddy 或用户态目录，再检查 `.workbuddy/memory/学习者画像.md`、`.workbuddy/memory/弱点档案/*.md`、`.workbuddy/memory/错因卡/*.md`、`.workbuddy/memory/*.md`；若是旧运行目录，再检查 `复盘引擎/学习者画像.md`、`复盘引擎/弱点档案/*.md`、`复盘引擎/错因卡/*.md`、`复盘引擎/学习记录/*.md`。只有这些候选路径都实际不存在或不可读时，才允许输出冷启动，并应说明已检查的路径。`reference/个人方法速查卡.md` 是掌握后写入的正向沉淀文件，缺失不代表没有错因卡/弱点档案。

- **考我快路径硬前置（先验后报，最高优先级）**：除非本轮**实际读取到至少一个非空弱点档案文件**（含真实弱点条目，排除 `*-template.md`、`README.md` 以及 0 条数据的空 `学习者画像.md`），否则**严禁**输出“已读到你最近弱点：<key>（错 N 次）”这类语句，**严禁**臆造弱点名、错误次数或难度档；此时必须先逐条列出已检查的状态路径族（每条标注 读到/未读到/空模板），再输出冷启动兜底。只有确有非空弱点档案时，句中的 `<key>` 与错误次数才能出现，且必须逐字来自该文件。
- **考我快路径**：用户说“考我/复习”时，先只读 `学习者画像.md` 和 `弱点档案/*.md`，不要先读方法库、题库全文或所有错因卡正文。若读到任一弱点档案，必须在 10 行内直接出 1 道方法工作流题：开头写“已读到你最近弱点：<key>（错 N 次），本次按【难度档 X】考你”，随后标注 `非真题 · 方法自测 · 不计真题正确率`，并基于该弱点档案的“下次出题策略 / 每次错法 / 方法掌握度”发问。快路径题只能问公式/方法选择、触发词、陷阱预判、上次错因归因；禁止编带数值、年份、企业/GDP等材料场景、四个选项或需要计算具体结果的仿真题。题干写成纯概念问法，例如“看到连续两期增长率，求跨期总增长率时，公式是什么？最容易漏哪一项？”用户答完后，才允许读取对应方法卡或错因卡进行判定。
- **考我门禁**：用户只说“考我/复习”且当前回复没有实际读到可用的到期错因卡、已核验题库或学习记录时，禁止生成普通言语题、仿真真题、仿真计算题或自编材料题；也不得先问“想练哪种题型”后直接出普通题。必须输出冷启动兜底（同上）。
- 用户在冷启动后选择题型时，只能出“方法工作流题”，每题必须显式标注 `非真题 · 方法自测 · 不计真题正确率`；结果只记方法掌握度，不计真题正确率。

## 考我 / 方法工作流题 批改后自动回写闭环

用户答完考我题、本轮批改完成后，只要弱点档案路径明确且可写，**必须一次性自动回写以下全部，绝不等用户追问"是否也写画像/学习记录"**：

1. **弱点档案**（对应 `模块-题型-核心考点`）：追加本轮复习记录、掌握度变化、难度档变化。
2. **学习者画像**：同步该弱点的掌握度 / 难度档 / 复习状态（错因表与模块强弱对应行一并更新）。
3. **学习记录**：新增本轮考我记录，含本轮精确得分 `x/y`。
4. **错因卡复习记录**：若能定位到原错因卡，追加其复习记录；**若定位不到，必须明确写“未定位到原错因卡，已写 弱点档案+画像+学习记录”**。

- **批改输出末尾必须列出所有实际写入的文件路径**（弱点档案/画像/学习记录/错因卡逐条）。
- **严禁**只说“弱点档案已更新 / 掌握度升至 X”却不同时落画像和学习记录——三处（+可定位的错因卡）要么同轮全写、要么逐条说明哪条没写及原因。
- 某项写入失败时，明确说明**失败路径与原因**，不得笼统说“已更新”。

## 题型分发（读 references/protocols/）

识别题型后读取对应协议文件并套用其固定栏目：

1. 阅读理解、主旨、意图、细节、结语、标题、排序、填句 → `references/protocols/verbal.md`
2. 逻辑填空、选词填空、成语、实词、虚词、关联词、搭配、语境关系 → `references/protocols/cloze.md`
3. 资料分析、增长率、增长量、比重、平均数、倍数、基期、现期 → `references/protocols/data.md`
4. 数量关系、方程、枚举、代入排除、工程、行程、概率、排列组合、几何 → `references/protocols/quant.md`
5. 判断推理、定义判断、类比推理、逻辑判断、削弱加强、图形推理 → `references/protocols/judgement.md`
6. 错因诊断、为什么错、想太多、偷换、策略问题、错因卡 → `references/protocols/error-diagnosis.md`
7. 问库结构、字段含义、索引位置、`unit_id`、schema → `references/protocols/method-router.md`

## 方法库使用（读 references/method-libraries/）

- 先看入口 `综合方法库.md`，再按 `方法质量规则.md` 判级，再进对应分区 `gongkao-review/`、`advanced-methods/`、`data-notes/` 找具体方法卡。
- 不写死来源优先级；多分区命中时按题型契合度、证据质量、流程完整度、本题适用性择优。
- A/B 级可讲，C 级仅作检索线索，D 级跳过。
- 方法依据 = 方法卡方法论字段 + card id / 文件名（遵守上方“方法依据收口”铁律：不输出 `source-anchor-xxxx` 编号或逐句转写）。
- **先读后引（铁律 8）**：写出某个 `am-card-xxxx` / 文件名前，必须本轮真正读过该文件；没读到就写“方法库未核 / 无对应方法卡”，**禁止凭记忆或文件名猜测安卡号**，多题批量解答同理。
- 库里没覆盖就明说“方法库无依据”，不得把模型通用常识包装成公考复盘原方法。

## 词语辨析（自动检索，非独立命令）

- 词义辨析是【复盘/解法/考我】流程内的**自动支持资源**，不是独立用户命令——用户仍只说"复盘/讲解/考我"，不新增口令。
- 当题目涉及近义成语、实词、虚词、关联词搭配、词义轻重/感情色彩时，自动检索 `references/lexical-discrimination/groups/*.md` 中命中的词条，并以"词语辨析"小节展示命中的词条原文，用于热身、错因修复、弱点词记录与后续练习。
- 词语辨析内容**不得**当作"方法依据"，也不得当方法库证据；它只是辅助，与方法卡来源分开呈现。
- 本包只带模板 `groups/group-template.md`，无词条正文；用户按模板把词条放进 `lexical-discrimination/groups/` 后，自动检索才会真正命中，在此之前该能力为接口空载状态。

## 讲解 / 解法输出顺序（先讲后写，落盘不得吞掉讲解）

用户说“讲解这题 / 看解法 / 我选X：<题>”时，**必须先完成讲解、再落盘**，严格按以下顺序输出：

1. **题型识别**
2. **正确答案**（明确给出）
3. **当前题推理 / 计算过程**（完整步骤，能算的要算出来）
4. **用户答案判定与错因**：给了“我选X”就必须明说 X 对还是错；选错讲清错在哪一步
5. **方法依据**（方法卡方法论 + 来源文件名，遵守方法依据收口铁律）
6. **易错点 / 陷阱**
7. **自动落盘回执**：上面 1–6 全部输出后，才按【写回】写盘并回执文件路径

铁律：**落盘是最后一步，绝不能省略 1–6 只输出“已落盘”**。选错→写错因卡+弱点档案+学习者画像；选对→写学习记录，不硬写错因卡。

## 写回（有可写路径时）

**自动落盘硬规则（最高优先）**：**先讲解、后落盘**——落盘是讲解内容全部输出后的**最后一步**，**绝不能跳过或吞掉讲解**，更不能只输出一句“已落盘”就完事。讲解全部给出后，再**直接写盘，禁止反问“需要我存错因卡吗 / 要不要沉淀 / 是否记录”**。
- 当前工作目录已有 `复盘引擎/` 或 `review-engine/` 或 `.workbuddy/memory/` 时，直接写到其下对应子目录（`错因卡/`、`弱点档案/`、`学习记录/`）。
- 若以上都不存在，默认在当前工作目录**新建 `复盘引擎/` 并写入**（让累的用户也能一句话沉淀，不用再操作）；仅当宿主只读、写入失败、或目标卡确实不唯一时才询问。
- 写完用一句话回执实际写入的文件路径，不要只口头说“已记录”。

按对错分流，**不要选对了还硬写错因卡**：

- **用户选错（错题）** → 写/更新错因卡 → 并入对应弱点档案（次数+1、追加“本次怎么错”、更新难度档）→ 摘要冒泡到学习者画像。
- **用户选对** → **不写错因卡**；可改为写一条学习记录、或记录命中的词义辨析弱点词、或在掌握判定达标时更新个人方法速查卡。掌握判定写入 `reference/个人方法速查卡.md` 需：答对且能说出关键步骤，或同一考点连续两次答对。
- **【解法/讲解】意图也默认沉淀**（用户只想快速“沉”这道题、不想多聊时尤其重要，不必先要求自述）：可判错的错题→写错因卡；判对或无用户错答→写学习记录。即“讲解这道题”同样会落盘，不让累的用户白讲一遍。
- 当题面/答案不足以判对错（OCR 未核验、无正确答案）时，先存题面候选与待核对说明，不强行判错写卡。

模板见 `references/review-engine/`。多题考我/题库判分写学习记录时，以当前批次精确分数 `x/y` 为唯一准绳，百分比须由该分数换算。全程手动同步，不调用脚本。

## 学情总结 / 下步建议（读状态出报告，不只服务考我）

触发：“错题总结 / 我的错题 / 学情报告 / 我现在哪儿弱 / 该练什么 / 下步建议 / 提醒我复习 / 复盘进度”等。

1. 按【状态读取路径铁律】**实际读取** `学习者画像` + `弱点档案/*.md` + `错因卡/*.md`（+ `学习记录/`）。**先验后报硬前置**：没真实读到非空状态就不许编，输出“还没有错题记录，先复盘几道题或拍一套卷子进来，再来看总结”。
2. 输出简明报告，**所有数字与条目逐一来自读到的文件，禁止臆造**：
   - **总览**：错因卡总数、覆盖模块、整体薄弱面。
   - **薄弱点排序**：按 `模块-题型-核心考点` 列出错次最多 / 难度档最低的前几项，标错误次数，链接弱点档案。
   - **高频错因**：反复出现的错因类型（如 漏乘积项、转折方向判断、审题偷换、想太多……）。
   - **该复习提醒**：复习次数少、久未复习、难度档没升上去的错因卡，提醒优先再考。
   - **进步/已掌握**：已转“已掌握”的考点。
3. **下步建议**：给 2–3 条具体可执行建议——练哪个题型/考点、用什么方式（“考我这几张卡”/“再拍一套同类题”/“看某方法卡”），并可一句话引导“要不要现在就考我这几张？”。
4. 默认**只读汇总不写盘**；仅当用户要“生成一份学情快照/阶段总结”时，才把报告写入 `学习记录/`。

## 题库导入 / 整页拍照

- “把这页/图片/PDF/DOC 加入题库”“导入题库”“收进题库” → 只做 OCR/文本提取、切题、答案核验、结构化保存、导入报告；不讲解、不复盘、不自动判题。答案缺失/未核验/题答数量不符时关闭自动判题（fail-closed）。
- **整页 / 多页拍照复盘**（用户拍了做完的行测卷或答题卡，含对错）：
  1. 先识别并列一句清单：共 X 题，可判定 Y 题（其中**错 Z 题**），待核对 W 题。多页/多图要合并去重后统一清点。
  2. 对**判定为错的题：直接讲解（方法依据 + 错因），不逐题走复盘三问门禁**——三问只用于用户对单题主动要求“先考我”的场景；整页批量错题一律直接讲、不三问。
  3. 讲完**自动写错因卡**（每道错题一张）→ 并入对应弱点档案 → 摘要冒泡学习者画像；判对的题计入批次得分、记学习记录，不写错因卡。批量写学习记录用精确分数 `x/y`。
  4. **待核对题 fail-closed**：无正确答案、OCR 存疑、题答数量不符的，先收着标“待核对”，不判对错、不写错因卡，并在末尾列出待你确认。
  5. 仅当用户上传时**完全没说要干嘛**才简短一问“①只整理存档 ②讲错题并存错因卡（推荐）③逐题复盘先考你”；若用户已说“讲错题 / 复盘这套卷 / 帮我看错题”等，直接走第 2–4 步，不再问。
- 截图 OCR 可作题面候选；遇“题面与讲解不匹配/疑似截偏”不要自动丢弃，需结合题干关键词、选项、讲解主题交叉核对。
